## ГЛАВНОЕ ОТКРЫТИЕ СЕССИИ: семейство багов nft 1.1.6 (25.12 ядро)

**jhash на этом стеке неремонтопригоден** — входные регистры конкатенации
портятся ЛЮБЫМ предшествующим выражением в правиле (set-lookup,
iifname, meta mark match) И выражениями предыдущих правил traversal'а
(голый jhash в jump-подцепи всё равно читал мусор). Проявления, все
воспроизведены стабильно:

1. `ip proto . th dport` в concat — парсерный тупик (умирает на токене
   ПОСЛЕ `ip proto`); `ip saddr . ip daddr . th dport` синтаксически ОК.
2. Анонимная интервальная карта `map { 0-69 : M1, 70-99 : M2 }`:
   `nft -c` проходит, в голой пробной цепочке делит честно, в боевой
   цепочке (после set-lookup'ов) — ВСЕГДА первый бакет.
3. Нормализованная форма диапазона `mod 100 0-69` — не матчует никогда
   (счётчики на нуле); одиночные сравнения `< 70` без префикса — честно.
4. Гейт `meta mark 0xfff` перед jhash — всегда бакет 0 (t3 матрицы);
   set/iif перед jhash — то же (t1/t2/t4/t5 считали все пакеты = все
   `< 70`).
5. `< 100` отвергается («Value 100 exceeds valid range 0-99»);
   `<= 99` нормализуется в сломанную форму `70-99`.

**Отсюда пивот дизайна**: jhash → **numgen random каскад** (родная
схема mwan3: statistic random на NEW + connmark restore). Правило i
забирает `numgen random mod 100 < cut_i` от остатка, последний член —
безусловный остаток (без draw). Число берётся из prandom, а не из
регистров — префикс не мешает. Утверждения L2 построены на исходе
(успех ⟺ метка), рандомность приемлема. ОТКЛОНЕНИЕ от выбора владельца
(jhash) задокументировано в DESIGN.md §2 — на приёмке спросить явно.

## БЛОКЕР СЕССИИ 2 (первым делом)

**numgen random НЕ равномерен на уровне потоков.** Последние замеры:
6/6 потоков к A получили mark=400 (должно быть ~30%); ранее 23×200/2×400.
Пакетный счётчик при этом ~65/35. Гипотезы: (а) random квантован
per-CPU/на батч, (б) «random» в этой сборке ведёт себя как hash от
чего-то постоянного, (в) малые выборки + кластеризация порта.

Первый шаг завтра — ЧИСТЫЙ декильный тест numgen (прерван синтаксической
ошибкой PowerShell-квотинга `while...done`; заливать ЧЕРЕЗ ФАЙЛ
`docker cp`, НЕ через sh -c с кавычками):

```
# файл probeD.nft (LF!):
add chain inet wanguard probeD { type filter hook prerouting priority -140; policy accept; }
add rule inet wanguard probeD numgen random mod 10 0 counter comment "d0"
... (d0..d9)
# затем 40 curl с клиента, прочесть счётчики d0..d9
```

### Кандидаты-замены (по убыванию предпочтения)

1. **`statistic random probability 0.70`** — РОДНОЙ механизм mwan3
   (iptables statistic --probability). nft умеет: `statistic random
   probability 0.70`. Каскад: rule1 probability 0.70 → M1; rule2
   безусловный → M2 (для 3 членов: 0.33, затем 0.5, затем остаток).
   Вероятно не зависит от регистров (как numgen). Проверить ПЕРВЫМ.
2. **numgen inc каскад** — `numgen inc mod 100 < 70`: глобальный счётчик
   инкрементируется на каждый пакет → новые потоки ротируются по
   членам детерминированно. Минус: счётчик на ПРАВИЛО — правило 2
   считает только дошедшие до него пакеты; в каскаде это ок
   (доля = остаток). Детерминированно = тестопригодно.
3. Если оба сломаются так же — **jhash в ОТДЕЛЬНОЙ таблице на prio
   -160** (первая таблица, трогающая пакет, до conntrack/mark-цепочки):
   голые правила, гейт по ether saddr ЛИТЕРАЛОМ (без set — может,
   именно set-lookup'ы главных таблиц травят регистры; в t1 литеральный
   MAC + jhash дал 60 матчёв — но спред не проверен!).

L2-харнесс НЕ трогать: он агностичен к механизму (исход ⟺ метка).
L1-обновить ожидания тегов под выбранный механизм (сейчас: `wg:lb:s70@200`
/ `wg:lb:s100@400`, последний член без numgen).

## Инфраструктурные находки (не повторять грабли)

- Лабовые адреса — ТОЛЬКО TEST-NET/benchmark (203.0.113/198.51.100/
  192.0.2/198.18): 172.30.x попадает в local_v4 (172.16/12) → правила
  с `ip daddr != @local_v4` не матчили НИЧЕГО (корневая причина первых
  «немаркированных» потоков).
- Якорь weak-host: адрес, принадлежащий eth1, отвечает и через eth0 —
  «честный таймаут» неверной пары умирает. Лечится таблицей
  `anchor_isol` на якоре (iifname != "ethX" ip daddr <адрес-X> drop).
  NB: собственные адреса якоря изнутри самого якоря больше не пингуются
  (iif lo) — чек готовости только по 127.0.0.1.
- ip_forward — только `docker run --sysctl` (proc/sys в контейнере RO).
- eth3 перед enslave в br-lan — `ip addr flush` (дубль connected-маршрута
  eth3+br-lan = асимметричная чёрная дыра), default пересадить на wanA
  (docker пересаживает default на последний подключённый net).
- Смоук L2 — минимум 8 попыток (одиночный curl честно висит в ~30-50%
  при случайном бакете — это НЕ поломка).
- Windows-квотинг: `<` в sh -c через docker exec уходит в редирект;
  многострочные nft-батчи — только через `docker cp` + `nft -f /tmp/x`
  (PowerShell-пайплайн возвращает CRLF). lab-up.sh запускается из Git
  Bash: cygpath -m + MSYS_NO_PATHCONV уже в скрипте.
- Пустой interval-сет (@mac_a) СЧИТАЕТ ВСЁ (a-rule насчитала 342
  пакета) — отдельная неисследованная странность того же семейства.
