# SPIKE #27 — вердикт (проект, ожидает решения владельца)

Статус: **рекомендация ADOPT**. Все батареи лабы зелёные чистым прогоном
(LAB-ALL-GREEN: net → client → up → L1 → L2 → L4 → L5, 2026-10-29,
ветка `spike/lb`, HEAD 989939c). Роутер и основной сьют (87/87) не
тронуты; proxy (mark 300) и wg_moscow в LB не участвуют — границы из
issue соблюдены.

## 1. Что построено

- `direct-lb`: группа с `list member_iface` + `weight_<iface>`; слоты
  по ОТСОРТИРОВАННОМУ имени члена (mark/table/prio стабильны при смене
  весов). Рендер разворачивает группу в N слотов аллокации —
  reconcile/сироты/#24-flush переиспользованы без изменений.
- Маркировка: stick-правило (ct-реставрация + return) + каскад
  `numgen random mod 100 < cut` (mwan3-схема: random на NEW +
  connmark-restore), последний член — безусловный остаток.
- wand-tick: члены LB наблюдаются (wand_wans), смерть члена →
  `lbover:<g>:<member>><live>` → member_live → слот переезжает на
  живого, мёртвому egress — целевой #24-flush; failback автоматически.

## 2. Живые находки PoC (nft 1.1.6 / ucode; ОБЯЗАТЕЛЬНЫЕ к переносу)

1. **jhash на этом стеке неремонтопригоден** → ПИВОТ на numgen random
   (согласие владельца 2026-10-29): входные регистры конкатенации
   портятся любым предшествующим выражением правила И traversal'ом
   предыдущих правил; interval-map → первый бакет; `mod 100 0-69` не
   матчует никогда; гейт → всегда бакет 0; `ip proto . th dport` —
   парсерный тупик.
2. **Member-правило без `return` = каскад не каскад**: правило без
   вердикта не завершает traversal, безусловный остаток перезаписывал
   mark → 100% потоков последнему члену. Именно это было «блокером
   сессии 1» («numgen random неравномерен») — draw'ы всегда были
   честными (29/40 первых SYN ≈ 72.5% при ожидаемых 70%).
3. **Каскад — порядок-чувствительная структура**: тег-дифф добавляет
   правила append'ом в конец цепочки; замена одного member-правила
   (смена веса) ставила draw ПОСЛЕ остатка → снова все потоки одному
   члену. Фикс: изменение любого member-тега = перерендер всего
   каскада группы. L1 теперь проверяет порядок хэндлами
   (stick < draw < remainder — при рендере И после flip'а).
4. ucode здесь не хоистит function-декларации (tick-path использует
   ранний `lb_member_ifcs`).

## 3. Метрики (лаба, виртуальные veth — абсолюты memory-speed)

- Распределение ≈ весам: 60 потоков → draw 47 / остаток 13 (78/22 при
  70/30, биномиальный шум); биекция «исход ⟺ метка» точная на сотнях
  потоков через L2/L5.
- Полоса: iperf3 single-WAN 15 034 Mbit/s → агрегат (оба WAN
  параллельно) 28 294 Mbit/s = **1.88×** — пути физически параллельны,
  полоса суммируется.
- Прилипание: 9-10 riders через смену весов в полёте — все докачались,
  метки не двигались, stick-counter 849→10352/592→14948 (реставрация
  реально обслуживает пакеты).
- Failover: down→lbover→слот на живом→#24-flush→failback→слоты на
  declared; zero-alive — fail-open (помеченные lookup'ы падают в main).
- MTU: 20MB через wan1 при MTU 1436 — PMTUD удержал (без MSS-clamp
  медленно; на роутере fw4-clamp стоит, конфликтов «mark до clamp» нет).

## 4. Честные ограничения

- Прилипшие потоки переживают смерть члена как ПРОД-свойство (публичные
  IP без маскарада); в лабе (masquerade + якоря на своих мостах)
  доказуем только control-plane + свежие потоки после recovery.
- Польза CGNAT-контеншена Rostelecom не измерялась — опциональное живое
  окно УЖЕ ПОСЛЕ adopt (по DESIGN §6 «пользы нет» — тоже валидный исход).
- nft 1.1.6 регистровые баги не наши чинить — задокументированы, оба
  грабельных требования (return; порядок каскада) защищены ассертами L1.
